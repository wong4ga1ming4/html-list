# HTML List 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个自托管的行式书签列表站，统一管理上传的自包含 HTML 文件与外部链接。

**Architecture:** 单进程 Next.js 全栈应用：客户端组件主页 + REST route handlers；SQLite 只存元数据，HTML 文件存 `DATA_DIR/files/`，`/p/[slug]` 路由从磁盘读取返回。Docker 多阶段构建单容器部署。

**Tech Stack:** Next.js 15（App Router）+ TypeScript、better-sqlite3、Tailwind CSS v4、nanoid、vitest。

**Spec:** `docs/superpowers/specs/2026-09-30-html-list-design.md`

## Global Constraints

- Node ≥ 20；Next.js 15 App Router + TypeScript strict；路径别名 `@/*` → `./src/*`
- 数据库：better-sqlite3，每次打开连接执行 `PRAGMA journal_mode = WAL` 和 `PRAGMA foreign_keys = ON`
- 数据位置：`DATA_DIR` 环境变量（本地默认 `./data`，Docker 内 `/data`）；数据库文件 `DATA_DIR/html-list.db`；上传文件 `DATA_DIR/files/{slug}.html`
- slug：nanoid，10 位小写字母数字；文件名正则 `^[a-z0-9]{10}\.html$`，冲突重试最多 5 次
- 上传限制：`MAX_UPLOAD_MB` 环境变量默认 20，仅接受 `.html` 后缀（大小写不敏感），超限 413
- API 错误统一 `{ "error": string }` + 恰当状态码；错误信息为中文（直接展示给用户）
- 时间戳：ISO 8601 UTC，SQL 默认值 `strftime('%Y-%m-%dT%H:%M:%SZ','now')`
- 无鉴权；无运行时外部网络依赖
- 所有书签链接 `target="_blank" rel="noopener"`；UI 为亮色主题、行式列表（非卡片网格）
- 书签列表排序：`created_at DESC, id DESC`；分类排序：`sort_order, id`
- DTO 不暴露 `file_name`（内部字段）；UI 测试按 spec §9 只做数据层/API 集成测试 + Docker 冒烟，页面用 `npm run build` + 手动清单验证

## Review Focus

实现时最容易踩、且任务核心测试未覆盖的五类输入（每条已在所属任务中补测试）：

1. **搜索词含 SQL LIKE 通配符**（`%`、`_`、`\`）→ 应按字面匹配而非匹配全部/报错 → Task 4 测试 `搜索词含 % 时不当作通配符`
2. **重复分类名** → UNIQUE 约束抛错应转为 409，而非 500 → Task 3 测试
3. **书签指向不存在的 category_id** → 应 400 而非 FK 异常 500 → Task 4 测试
4. **`/p/[slug]` 路径穿越**（slug 或库中被篡改的 file_name 含 `../`）→ 必须 404，绝不读 files 目录之外的文件 → Task 6 测试
5. **纯空白标题**（`"   "`）绕过必填校验 → 应 trim 后判空返回 400 → Task 4/5 测试

  updated_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX IF NOT EXISTS idx_bookmarks_category ON bookmarks(category_id);

**Interfaces:**

- [ ] **Step 1: 写 Dockerfile（多阶段，三阶段同用 node:20-alpine）**

```dockerfile
FROM node:20-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN apk add --no-cache python3 make g++ && npm ci

FROM deps AS builder
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production DATA_DIR=/data PORT=3000
RUN addgroup -S app && adduser -S app -G app
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
RUN mkdir -p /data && chown -R app:app /data /app
USER app
EXPOSE 3000
CMD ["node", "server.js"]
```

builder 与 runner 同底镜像，保证 better-sqlite3 的 musl 原生模块直接可用。

- [ ] **Step 2: 写 docker-compose.yml / .dockerignore / README.md**

dockerignore：`node_modules`、`.next`、`data`、`.git`、`.claude`、`docs`。
README：一条命令启动、volume 备份说明、环境变量表（PORT/DATA_DIR/MAX_UPLOAD_MB）。
